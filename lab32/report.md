# Практична робота №14

### Завдання 1. Віртуальне середовище

Створено віртуальне середовище командою `python3 -m venv .venv`. Для активації використано `source .venv/bin/activate`.

Після активації команда `which python` показала шлях до інтерпретатора всередині `.venv`. Після `deactivate` команда `python` не знаходилася, що підтвердило вимкнення середовища.

### Завдання 2. Бібліотека tabulate

Установлено бібліотеку `tabulate` у віртуальному середовищі. Програма `task2.py` читає `data/expenses.csv`, пропускає порожні рядки й коментарі та підраховує кількість записів і суму витрат за категоріями.

Результат: 12 записів на загальну суму 1076.00.

Поза віртуальним середовищем програма завершилася помилкою `ModuleNotFoundError: No module named 'tabulate'`, оскільки бібліотека там не була встановлена.

### Завдання 3. Генерація QR-коду

За допомогою бібліотеки `qrcode` створено QR-код із контактними даними. Зображення збережено у файлі `contact.png`.

### Завдання 4. Файл requirements.txt

Командою `pip freeze > requirements.txt` зафіксовано встановлені залежності та їхні версії.

У копії проєкту `lab32_copy` створено нове віртуальне середовище й установлено залежності командою `pip install -r requirements.txt`. Програма `task2.py` успішно виконалася.

За командою `pip show tabulate` отримано:
- Version: `0.10.0`
- License: MIT
- Location: шлях до бібліотеки всередині `.venv`.

### Завдання 5. Версії та видалення бібліотек

Командою `pip install "tabulate==0.8.10"` установлено версію 0.8.10. Після `pip install --upgrade tabulate` версія оновилася до 0.10.0.

Після видалення `qrcode` командою `pip uninstall qrcode` запуск `task3.py` завершився помилкою `ModuleNotFoundError`. Це підтвердило, що програма залежить від цієї бібліотеки.

### Контрольні запитання

1. Навіщо потрібне віртуальне середовище?

Щоб ізолювати бібліотеки одного проєкту від інших проєктів і системного Python.

2. Як перевірити, що середовище активне?

Командою `which python` і перевіркою шляху до інтерпретатора. Також назва `(.venv)` зазвичай відображається в терміналі.

3. Чим відрізняються `pip freeze` і `pip list`?

`pip list` показує встановлені пакети, а `pip freeze` виводить їх у форматі, придатному для `requirements.txt`, із зафіксованими версіями.

4. Чому `.venv` додають у `.gitignore`, а `requirements.txt` — ні?

`.venv` містить локальні файли середовища, які можна створити заново. `requirements.txt` потрібен для відтворення залежностей проєкту.

5. Чим відрізняються `==` і `>=`?

`==` вимагає конкретну версію пакета, а `>=` дозволяє цю версію або новішу.

6. Які ризики встановлення невідомих пакетів?

Пакети можуть містити шкідливий код або небезпечні залежності. Варто перевіряти джерело, автора, документацію та встановлювати пакети з надійних репозиторіїв.
